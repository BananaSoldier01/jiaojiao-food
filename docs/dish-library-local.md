# 单菜菜谱库：实现与验证

日期：2026-10-13。v16 功能 / v17 加载优化说明；最新发布状态见 [发布记录](2026-10-13-v17-release.md)。

## 页面行为

原「往期」栏保留，并分为「菜谱库 / 每周归档」。菜谱库每张卡片是一道菜；同名合并，保留各日期的食材、步骤和来源。搜索同时匹配菜名与已明确归属本菜的食材，不搜原餐备注和同餐其他菜的食材。原周菜单仍可从详情打开。

现有七周共 113 条不重复餐次记录，整理出 147 个菜品条目、205 份菜品来源记录；130 个条目至少有一份可摘录的做法。这里是「菜单记录」，不代表全部实际吃过；未来日期和二选一计划仍标明原日期与备选。早期仅总览记录不补写食材或步骤。

## 内容处理

- 明确的独立菜分开；例如牛肉小馄饨与小油菜分开。
- 「番茄鸡蛋 + 口蘑 + 西兰花 + 蝴蝶面」根据原步骤合并为一道面，不机械拆成四条。
- 苹果奶酪牛肉饼与苹果洋葱奶酪牛肉饼的原料均有洋葱，归入同一菜名；不同日期用量仍分开。
- 每一条整理后的食材和步骤都是原文整行或精确摘录；不新编用量，不把另一道菜的整行食材借入。原餐提醒和完整搭配可展开回查。
- `assets/dish-catalog.json` 是静态结构化资料，仅存已核对来源 sources，菜谱在浏览器中按最新 HTML 生成，不需要后端数据库服务。

## 更新兼容

`assets/today.js` 仍是共用入口，自动加载 `dish-core.js` 与 `dish-library.js`；不要求每个周页再增加脚本引用。浏览器仅在打开菜谱库或搜索后读取目录、最新 HTML 和整理资料。

主页优先于同周归档，按日期与餐次去重；删除的记录不会单凭旧资料继续显示。旧整理内容只有在原菜名、食材、步骤、备注和归属标记全部匹配时才使用。若 Grok Bot 改了内容，自动保留新菜名和出处，但不会套用旧用量；未明确归属的独立食材/步骤暂不显示。可补下述轻量标记直接恢复独立详情，无需运行构建。

## 给 Grok Bot 的填写规则（v16）

原周更流程、六个栏目、meal-card、two-col、日期锚点和归档方式不变。新建或修改的菜单要自动显示独立食材和步骤，需在食材 li 和做法 li 上增加 `data-dish="不带份量的菜名"`，值与该道菜名称一致；同一条同时讲了两道菜，应按菜分别写条目，不能将整条随意归给其中一道。

```html
<h4>南瓜饼 + 小米粥</h4>
<div class="two-col">
  <div><h5>食材</h5><ul>
    <li data-dish="南瓜饼">本次确认的南瓜饼食材、用量和限定</li>
    <li data-dish="小米粥">本次确认的小米粥食材、用量和限定</li>
  </ul></div>
  <div><h5>做法</h5><ol>
    <li data-dish="南瓜饼">本次确认的南瓜饼步骤</li>
    <li data-dish="小米粥">本次确认的小米粥步骤</li>
  </ol></div>
</div>
```

对于「+」其实代表一道菜的原料组合，可在 h4 明确写 `data-dishes="番茄口蘑鸡蛋蝴蝶面"`；多道菜用 `|` 分隔，li 的 data-dish 采用相同名字。关键条件保留在相应菜的食材/步骤中，整餐背景仍放 note-inline。不要为了让系统归类而删掉选项、份量或限定。

不加这些标记也不会破坏原食谱，新的菜名仍能在库中检索，但未核对的新建或修改餐次（包括单菜餐）不会自动生成独立用量和步骤。旧菜谱无需逐周补标记。v16 发布后，Bot 按交接说明采用新规则。

## 开发核验

- `node tests/dish-core.cjs`：去重、食材隔离、备选、组合面、原文摘录、内容修订后旧映射失效及新周标记。
- `node tests/dish-library.cjs`：手机卡片/详情/版本、两级弹层、周归档、旧菜单、分页、故障重试和主页优先。
- `node tests/mobile-ui.cjs` 与 `node tests/mobile-reading.cjs`：原菜单功能回归。
- `node scripts/build-dish-catalog.cjs`：开发者在核对原文归属后重新生成快照，要求本地 Playwright；不是 Bot 的每周必做项。已存在记录发生变化时会拒绝重建，核对 `scripts/dish-curation.cjs` 的行归属后才能用 `--accept-reviewed-changes` 放行。

未做实体 iPhone Safari / 微信内浏览器检查。

本轮实际检查结果：dish-core、dish-library、mobile-ui、mobile-reading 均通过；覆盖 9 页、120 餐原展示、4 种宽度和网络失败重试。另核对「非虾馅」等否定文字不作为含虾食材命中。菜单 HTML 及周归档仅升级资源缓存版本，菜名、用量、步骤和图片未改；menu-ui.js、tabs.js 与采购等内容模板保持不变。

复查修正：无空格“或”也标为备选；括号内的原料选项不会把整道菜标成备选。苹果牛肉饼的合并仅保留在已核对的历史记录中，不对未来同名菜自动补入“洋葱”。

## v17 加载优化

资料去除重复的预计算菜谱并紧凑存储；来源、摘录和生成结果不变。脚本与网络读取并行，当前与已读取周页先显示，其余继续补齐，并提示当前结果尚未完整。打开详情时若仍在读取，提示稍后重开可查看补齐的日期版本。

请求合计最多四个并发，30 秒超时，临时失败自动重试一次；成功数据在当前页复用。两次仍失败则提示并提供手动重试，不把旧快照直接当最新菜单。新增 tests/dish-loading.cjs 覆盖渐进显示、13 秒慢响应、真实超时自动恢复、临时错误及永久错误。
