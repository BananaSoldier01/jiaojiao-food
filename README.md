# jiaojiao-food

家庭辅食周计划静态页。`index.html` 为当周；历史在 `weeks/`。

## 发布方式与分工

- 仓库：`BananaSoldier01/jiaojiao-food`。网站通过 GitHub Pages 发布，`main` 分支为线上版本；推送到 `main` 会进入站点发布流程。
- 用户与 personal agent（如 grok bot／蕉蕉辅食管家）讨论每周菜单，由管家按现有模板更新菜单内容、做法图片和归档入口，并直接推送到 `main`。
- Codex 负责前端、样式、脚本和新功能，完成相应验证后同步到 GitHub。
- 两边共同遵循本 README。涉及模板、文件结构或协作方式的变更，应在同一次改动中更新说明。

## 文件结构

| 路径 | 用途 |
| --- | --- |
| `index.html` | 本周菜单，包含总览、每日做法、采购、营养、提醒和往期入口 |
| `weeks/YYYY-MM-DD.html` | 每周归档，文件名使用该周周一的日期，例如 `weeks/2026-10-12.html` |
| `weeks/index.html` | 全部往期列表 |
| `assets/style.css` | 共用样式 |
| `assets/tabs.js` | Tab 切换及每日做法的锚点导航 |
| `assets/today.js` | 按浏览器本地日期标记当天内容 |
| `assets/recipes/*.jpg` | 做法步骤图 |
| `CNAME` | GitHub Pages 自定义域名配置，必须保留 |
| `.nojekyll` | 静态站点发布标记，保留 |

主页引用资源使用 `assets/...`，归档页使用 `../assets/...`。README 不记录站点域名，域名配置以 `CNAME` 为准。

## 菜单模板约定

管家每周沿用以下结构，Codex 开发功能时保持兼容。确实需要更改结构时，先告知用户并协调管家调整每周写法，再实施变更。

1. 保留六个 Tab，对应 `data-tab` 值不得更改：`overview` / `daily` / `shop` / `nutrition` / `notes` / `archive`。
2. 每天一个 `article#dMMDD.day-article[data-date]`：例如 10 月 12 日使用 `id="d1012"`、`data-date="2026-10-12"`。每日锚点及相关链接保持一致。
3. 每天包含三个 `div.meal-card`，对应早餐、午餐、下午餐。每个餐次内部依次保留：

   ```text
   p.meal-time
   h4
   .pillars
   .two-col（左侧食材，右侧做法）
   figure（做法图，可选）
   p.note-inline
   ```

4. 周览卡片使用 `a.week-card[data-date]`，链接指向对应每日锚点。每个餐次用 `<em>` 写餐次名、`<span>` 写菜名，例如 `<em>早餐</em><span>菜名</span>`；午餐、下午餐同样处理。

## 每周内容更新

1. 开始前拉取最新 `main`，确认没有与 Codex 同时编辑同一个文件。
2. 根据用户讨论确认的菜单更新 `index.html`，保持总览、每日做法、采购清单及相关说明一致。
3. 创建或更新该周的 `weeks/YYYY-MM-DD.html`，同步菜单内容，并使用归档页的相对资源路径。本周已有归档时，后续菜单修订也同步到该归档。
4. 更新主页往期入口与 `weeks/index.html`，保留已有历史归档。
5. 检查日期、每日锚点、三餐内容、图片和归档链接，再按下方流程同步 GitHub。

## 协作与同步流程

- 开工前检查本地改动并拉取最新 `main`；存在未提交改动时先确认归属，保留对方及用户的工作，不直接覆盖或丢弃。
- 两边不要同时修改同一个文件。内容与前端可能都涉及 `index.html`、`weeks/*.html`，不能仅凭分工认为不会冲突；动手前通过用户协调编辑范围和时间。
- 提交前查看差异，只提交本次任务所需文件。菜单更新检查内容、资源和链接；前端功能变更还需验证相关页面交互及归档兼容性。
- 推送前再次拉取最新 `main`。本地已有提交时，可使用 `git pull --rebase origin main` 整合远端更新；出现冲突时核对双方意图，保留最新菜单和本次有效改动，不整文件覆盖。
- 整合远端改动后复查受影响内容，再推送到 `main`。若远端又有更新导致推送被拒绝，重复整合和检查，不强制推送。
- 推送后确认远端提交。GitHub 推送成功与线上发布验证分别记录，未检查线上页面时不宣称线上验证通过。
- 新增文件、调整结构或改变约定时，同步更新本 README，让 Codex 与管家使用同一套规则。

## 手机界面与历史搜索（2026-10-12）

### 管家每周照旧更新

继续更新本周 HTML、对应周归档、主页往期入口及 `weeks/index.html`，不需要生成 JSON 索引、运行构建命令或为每餐新增图片。六个 Tab、每日文章、餐次卡片与周览结构均保持原约定。

- 沿用最新页面的共用资源引用（当前为 `?v=13`）。这个版本号用于前端更新时刷新缓存，由 Codex 维护，普通菜单更新无需修改。
- 做法图仍可选，使用既有路径规则。没有图片的餐次可以正常显示。
- 「今天吃什么」从当前页面的周览卡片自动生成，仅当页面包含浏览器本地今天的日期时出现。本周情况与提醒默认折叠，可手动展开；内容未删减。
- 不要把浏览器运行时生成的搜索弹层、今日卡片或折叠容器复制回源文件；管家继续编辑仓库原有 HTML 模板即可。

### 搜索如何工作

`assets/today.js` 同时负责当天标记、总览增强与历史搜索。使用既有脚本入口，避免每周维护额外引用。`assets/tabs.js` 仍负责 Tab 和每日跳转，`assets/style.css` 负责手机优先的显示。

点击页头「搜菜名」后，浏览器才读取 `index.html` 和 `weeks/index.html`，从归档列表及主页链接发现各周菜单，再解析 HTML。结果在当前页面内存中复用，重新打开或刷新页面可重新读取更新后的菜单；不使用持久化索引。

- 搜索范围是菜名（`meal-card h4`；只有周览的旧归档则读取周览菜名），支持用菜名中出现的食材词检索，不检索完整食材表或做法正文。
- 结果展示日期、原有餐次名与菜名，按日期倒序排列；点击进入对应日期的做法或旧归档总览。
- 按日期和餐次去重，本周 `index.html` 优先于同周归档；保留旧菜单的「上午／下午」等餐次名。
- 早期仅含总览的归档，通过周一文件名和卡片顺序确定日期，运行时生成 `menu-YYYY-MM-DD` 锚点；不要改变这类旧页的卡片日期顺序。
- 网络失败会显示「结果可能不完整」及重试按钮，不把未加载内容当作没有匹配。加载有超时，每批最多读取四周；打开普通菜单时不预加载全部历史。
- 搜索需要通过 HTTP(S) 访问（线上站点或本地预览服务），直接双击 HTML 的 `file://` 模式不用于功能验收。

历史较多时，首次搜索需要下载更多页面；届时再评估自动构建索引，目前不把索引维护工作交给管家。

本次验证范围和限制见 [手机改版与搜索验收记录](docs/2026-10-12-mobile-search-checks.md)。

## 四页手机交互（v14）

`assets/menu-ui.js`，负责餐次选择、备食材/看做法切换、图片放大、采购分类勾选、营养展开、提醒分组和往期月份标题。共用资源版本为 `v14`。

- 原有六个 Tab 与食谱源结构保留，历史两餐直接按原餐次显示；最早的总览归档不补造食谱。
- 搜索继续从 HTML 读取，不需要 JSON；结果用 `?meal=餐次序号#日期锚点` 直达对应餐次，原有日期锚点仍兼容。
- 食材/采购勾选仅在当前页面会话保留，刷新或离开页面后清空，不跨设备同步。
- 营养重点由内容中的 `data-nutrition-summary` 明确提供。旧页保留原记录，不猜测重点或生成营养判断。
- 提醒使用 `data-note-group` 显式分类；未知或缺少分类的内容完整保留。
- 采购推荐用 `ul[data-shopping-items]` 明确一项一行；旧版整段文本继续兼容。

完整填写规则与示例见 [grok bot 固定模板与交接说明](docs/grok-bot-handoff.md)，可复制内容块见 [内容模板](templates/content-sections.html)。旧页不需要每周回填新字段。

本地检查：先在项目根目录运行 `python3 -m http.server 8765 --bind 127.0.0.1`，然后在已安装 Playwright 与 Chromium 的环境运行 `node tests/mobile-ui.cjs`。可用 `BASE_URL` 指定其他本地服务地址。不需要管家每周配置测试环境。

本次整合的本地验收范围、旧归档修复与未验证项见 [本地验收记录](docs/2026-10-12-integrated-local-checks.md)。
